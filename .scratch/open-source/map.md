# Open-source Naiad

Label: wayfinder:map
Charted: 2026-09-18

## Destination

A spec for Naiad's first open-source release: CLI verbs over Workflows and States that hide paths and TOML from the author while keeping the file the truth; the library revised to store authored workflows; a skill-free starter workflow shipping in place of the personal one, which stays in the repo unoffered and unmentioned, with its `naiad.toml` convention made its own; `naiad.toml` and the two keys it carries retired from Naiad; the Queue listing showing the current State beside the status; documentation as markdown in the repo; and the release itself: PyPI install, license, README, repository naming. Handed to `/to-spec` when no ticket remains.

## Notes

Domain: Naiad is a workflow orchestrator whose purpose is to remove manual instantiation of Claude Code sessions and to contain context bloat. Vocabulary in `CONTEXT.md`; decisions in `docs/adr/`; tracker conventions in `docs/agents/issue-tracker.md`. Every session consults `/grilling` and `/domain-modeling`; nothing is built inside the map, tickets resolve decisions.

Standing decisions from the charting grill (2026-09-18), each ticket builds on them rather than reopening:

- The primitive is CLI verbs shaped like `naiad queue`: `naiad workflow list|show|new|rm` and `naiad state list|show|add|rm|set|move|set-prompt`, every state verb naming its workflow explicitly. A Claude Code skill over them is fog, not a ticket. (Amended by "The verb surface": the Protocol's announce verb becomes `naiad announce`, so `naiad state` is authoring only; `rename`, `check`, `unset` and `next` join the verbs.)
- The TOML file stays the truth and hand-editing stays valid; verbs are the surface an author never has to leave.
- Prompts are entered through `$EDITOR`, or `--from <file>` / stdin for scripting.
- Every writing verb reloads the file after writing and rolls back on failure; `naiad workflow check` exists for hand-editors.
- `naiad workflow rm` refuses while a queued Entry or live Run addresses the file, naming them. `naiad state rm` refuses while another State names it in `next`; `naiad state` rename rewrites those edges.
- `naiad state add` lands before the terminal State unless `--after`/`--before` says otherwise; `move` reorders.
- `terminal = true` stays as the ending's marker (a Workflow is a state machine with final States; a `naiad done` verb would move the ending to the agent's judgment; inference from "no Prompt, no next" is implicit). `naiad workflow new` scaffolds a terminal `done`; no verb ever asks about it; `show` and `list` name a State's kind (Prompt, Gate, Branching, Reserved-question, Terminal) out loud.
- The library becomes a store for authored workflows as regular files; ADR 0037 is revised, its install refusal kept. (Charting also said shipped ones stay symlinks; reversed by "Where shipped and authored workflows live": Naiad makes no symlink, the starter is copied on request.)
- `naiad.toml` and `naiad init` are dropped from Naiad: the engine never read the file, and its two keys (`companions`, the pull-request opt-out) are one workflow's convention.
- Install path is PyPI (`uv tool install naiad`). (Amended by "The public repository": the distribution is `naiad-cli`, so `uv tool install naiad-cli`; the command stays `naiad`.)
- tmux is a prerequisite, not an option: a Session is a tmux session, delivery is keystrokes into a pane, and Adoption refuses outside one. Documented, never worked around in this effort.
- Naiad notifies for exactly two reasons, the Run needs a human (a Gate, an escalated or reserved Question, a hold, silence, idleness, an unknown State, a dropped Clear) or the Run is over; every one parks the Run. (Amended by "A State that tells the operator on entry": a third telling, the Report, informs without parking.)
- The engine and Protocol change only where a Workflow declaration needs a reader (the library store, the Queue's State column, a State that tells the operator on entry); anything project-specific lives in Prompts.

Hand-off (2026-09-27): no open tickets and no fog remain. A fresh session loads this map plus its resolved tickets and runs `/to-spec`, then `/to-tickets`. The spec carries: ADRs 0049, 0050, 0052, 0054, 0055, 0056 and 0057 as written (plus the tracked ADR citations restated inline per "The public repository"); the glossary edits already in `CONTEXT.md` (Standing State, Report, Reserved Question widened, Gate State, Answer log, Companion repository removed); the starter draft on branch `prototype/starter-workflow` and the verb stub on `prototype/verb-surface` as fixtures; the PyPI findings on `research/pypi-publishing`; and a QA plan whose spine is one starter Run to `done` on a throwaway repo from a clean `uv tool install naiad-cli`, plus the docs test that parses every `naiad` line.

## Decisions so far

- [Publishing to PyPI](issues/06-publishing-to-pypi.md) — `naiad` is taken by an empty 2016 project (PEP 541 transfer or a fallback name such as `naiad-cli`); trusted publishing via a pending publisher and `pypa/gh-action-pypi-publish` or `uv publish`; `pyproject.toml` needs readme, license, authors, classifiers, urls and `setuptools>=77`; `uv tool install` needs only the wheel. Findings on branch `research/pypi-publishing`.
- [Where shipped and authored workflows live](issues/02-where-shipped-and-authored-workflows-live.md) — the starter ships inside the package at `naiad/workflows/starter.toml`; `naiad install --starter` copies it into the library as a regular file the adopter owns, refuses to overwrite an edited one without `--force`; the library is a store, hand-made symlinks stay valid and verbs write through them; `naiad workflow rename` exists; ADR 0049 amends 0037.
- [The starter workflow](issues/01-the-starter-workflow.md) — `plan` → `review` (Gate) → `implement` → `verify` → `ship` → `done`, three Clears, no branching, no settings, no `[answerer]`; `PLAN.md` on the Working branch carries the context and `ship` removes it; a pull request through `gh` when it can, the branch name otherwise; `{task}` and `{branch}` only. Proved by one Run to `done` on a throwaway repo; draft on branch `prototype/starter-workflow`.
- [The verb surface](issues/03-the-verb-surface.md) — `naiad announce` replaces `naiad state STATE`; `naiad workflow list|show|new|rm|rename|check|set|unset` and `naiad state list|show|add|rm|rename|set|unset|move|next|set-prompt`, generic `set`/`unset` over a key table printed by `--help`, `name`/`prompt`/`next` verb-owned; one kind column (`prompt|gate|terminal`) plus marks; declared order is the path and `next` the exception; Prompts from `$EDITOR`, `--from`, `--prompt`; `next` takes positionals, `--none` clears, none opens a stdlib picker; `terminal` settable; `new` scaffolds only `done`; the `questions` flag polarity follows the Answerer ticket. Stub on branch `prototype/verb-surface`.
- [The Answerer is opt-in and visible](issues/11-the-answerer-is-opt-in-and-visible.md) — the human is the default: no `[answerer]` table means every Question parks the Run for the human, the table flips the file default, a State overrides either way with `questions`; the Answerer needs no table to exist; headless stays and the Answer log is the visibility, so it gets a reading verb ("Reading a Run's Answers"); Reserved Question widens; `add --auto` opts a State in; ADR 0050 amends 0046.
- [The State column in the Queue listing](issues/04-the-state-column-in-the-queue-listing.md) — the listing shows the Run's Standing State (new glossary term) right after the status word: `-` while waiting, the start State before the first Announcement, the latest Announcement's State otherwise, `done` Runs included, with no mark for a Wait or Question, no Subject and no header; the start State is recorded on the Run at kickoff, so `standing_state` and the listing never read the Workflow; old Runs without that record show `-`.
- [What becomes of the personal workflow](issues/05-what-becomes-of-the-personal-workflow.md) — it stays at `workflows/matt-pocock.toml`, tracked and readable but never offered by install or named in adopter docs; `naiad.toml` becomes its own `.matt-pocock.toml` (Prompt edited to match), ADR 0052 amends 0018/0048/0043; **Companion repository** leaves `CONTEXT.md`; the shipped-workflow test covers both files; its tuning notes and smoke doc go untracked with the ADRs; the library link is untouched.
- [The license](issues/07-the-license.md) — code is MIT, `Copyright (c) 2026 Janriz Libres`; the two Workflow files (`naiad/workflows/starter.toml`, `workflows/matt-pocock.toml`) are 0BSD so a copied starter owes no attribution; `LICENSE` (MIT, naming the 0BSD files) plus `LICENSES/0BSD.txt`, `license = "MIT AND 0BSD"` in `pyproject.toml`, no SPDX header in the TOML; ADR 0056.
- [The public repository](issues/08-the-public-repository.md) — repo and PyPI distribution both `naiad-cli`, command `naiad`, no PEP 541; the repo stays public until release; at release `git filter-repo` strips `docs/adr/`, `CONTEXT.md`, `docs/agents/`, `docs/smoke/`, `.scratch/` from every commit and rewords every message free of citations, then the repo is deleted, recreated and pushed; those paths plus `CLAUDE.local.md` go untracked via `.git/info/exclude`, laptop-only; tracked ADR citations restated inline; `AGENTS.md` stays, trimmed; contributions accepted under MIT/0BSD, no CLA, `CONTRIBUTING.md`; ADR 0054. (Amended by "The documentation set": `docs/smoke/` is renamed `docs/maintainer/` before the filter.)
- [The documentation set](issues/09-the-documentation-set.md) — `README.md` (problem-first, `bypassPermissions` warning, install to a finished starter Run, Concepts, uninstall, Status), `docs/running.md`, `docs/workflow-authoring.md` rewritten task-first with the starter explained, `docs/how-it-works.md` (Protocol paraphrased, hooks), `CONTRIBUTING.md` taking the dev section, `AGENTS.md` trimmed; no command reference (`--help` is it), no changelog; a test parses every `naiad` line in the docs; `docs/smoke/` becomes the untracked `docs/maintainer/` holding the personal file's notes.
- [A State that tells the operator on entry](issues/10-a-state-that-tells-the-operator-on-entry.md) — `report = true` on a State makes each Announcement of it send a **Report** (new glossary term): a third `Notification` member and a separate `Report` Action, with its own record and `reported` log kind, so it never parks and never discards the Belief; fires on the first Tick that sees the Announcement, without waiting for a turn end; message `entered <state>: <subject>` on all three legs, ntfy priority 2; Questions and start States never report; refused on Gate and Terminal States; State key only; the starter declares none; ADR 0055.
- [What an adopter can configure, and where](issues/12-what-an-adopter-can-configure-and-where.md) — no new Workflow key and no new Naiad variable: `bypassPermissions` stays fixed for Sessions and the Answerer, containment is the machine's job (ADR 0057); every tuning constant stays; `NAIAD_HOME`, the notification legs and `claude` on `PATH` are unchanged; `naiad install` honours `CLAUDE_CONFIG_DIR` for the hooks (and the skill, if the spec confirms Claude Code reads skills there); `docs/running.md` gets a "What you can configure" section.
- [naiad doctor and the refusals](issues/13-naiad-doctor-and-the-refusals.md) — one set of checks, two callers: `naiad doctor` reports every finding (fail/warn/info) and repairs nothing, and `run`, `watch`, `adopt` and the Supervisor refuse on the first failure-level check (`tmux` and `claude` on `PATH`, `NAIAD_HOME` writable, hooks present in the `CLAUDE_CONFIG_DIR`-aware settings file and naming this `naiad`); the `claude` version floor, the adopt skill, unloadable library entries and a tmux server's `PATH` warn; notification legs are information; `queue add`, Protocol and hook verbs never check; an Answerer that can't run still escalates, with a readable reason; install ends with doctor's report.
- [What the agent and the human each know at a Gate](issues/14-what-the-agent-and-the-human-each-know-at-a-gate.md) — the Gate notification adds `next: <state>` (or the candidates); the announce verb's reply, where Naiad will park on the Gate, tells the agent a human takes it from here, to end its turn, and the Protocol's own expectation sentence; nothing is typed into the Session; every other Announcement's reply is unchanged; the rejection list stays; the docs tell the human to send a verdict, not a State name; **Gate State** gains one sentence, no ADR.
- [Reading a Run's Answers](issues/15-reading-a-runs-answers.md) — `naiad queue answers <entry|run>` (required, no latest default) prints one numbered block per Question: State, Question, options, and an outcome line `→ answerer:` / `→ yours:` / `→ abandoned:`, wrapped to the terminal; each log entry gains the Standing State it was asked from; human Questions show who took them, never the reply; the `queue watch` echo shortens to one line; the Finish and Gate notifications add `N answered by the Answerer — naiad queue answers <entry>` when N > 0; no ADR.
- [An unknown Workflow key is refused](issues/16-an-unknown-workflow-key-is-refused.md) — the loader refuses an unknown key at the top level, in a State or in `[answerer]`, naming the key, where it sits and the keys allowed there; every caller refuses alike through the one load path; no version key this release, since refusal already makes a newer file fail loudly on an older Naiad; no ADR.

## Out of scope

- A navigational documentation website. Markdown in the repo is the release's documentation; a site is a later effort once it stabilises.
- A `naiad done` Protocol verb replacing the terminal marker. Rejected in charting: it moves the ending from the declared Workflow to the agent's judgment.
- The Queue listing naming the reason for a park beyond the current State (escalated Question, dropped Clear, hold). The State column is in scope; the reason column is not.
- A watchable Answerer: a consultation run in its own tmux window the operator can take over, or a draft the human confirms before it is sent. Rejected in "The Answerer is opt-in and visible": the Answerer is opt-in, headless, and seen through the Answer log; a watched consultation needs a second adapter and a reply channel that is not a value (ADR 0002).
- A per-Run pull-request override (already deferred in `.scratch/deferred/issues/06-per-entry-pull-request-override.md`); belongs to the example workflow's convention, not to Naiad.
- A per-project default workflow, so `naiad queue add` needs no workflow argument in a repo that has chosen one. The workflow name is one word, and a project file the engine reads is what retiring `naiad.toml` removed; it returns as its own effort, with a rule of its own.
- A Claude Code skill over the verbs (`/naiad-workflow`) that interviews the author and writes the file. The verbs and the task-first authoring doc are this release's authoring surface; a skill is a layer over them that needs nothing changed, so it follows once adopters show where the interview is hard.
- A workflow file declaring the project keys its Prompts expect. The shipped starter expects none, so no adopter meets the problem in this release.
- A version key in the Workflow file format. Refusing unknown keys ("An unknown Workflow key is refused") already makes a newer file fail loudly on an older Naiad; a version returns only when the format has to break compatibility.
- A session adapter other than tmux. tmux is a documented prerequisite; an adapter is its own effort, only if the prerequisite proves to be the adoption blocker.
- Desktop notifications on Linux, where `osascript` does not exist. ntfy covers Linux; `docs/running.md` says the desktop leg is macOS only.
- A State key for the hang bound or the Wait budget. The bounds stay constants; returns only if an adopter hits them.
- A `naiad uninstall` verb. The README documents the manual steps.
- A test send to each notification leg (`naiad doctor --notify` or similar). Doctor stays read-only, so a send has no home in this release.
- A way to print a sample Protocol for a named Workflow and State. `docs/how-it-works.md` paraphrases the Protocol; only if asked.
