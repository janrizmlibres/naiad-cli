# A Prune takes orphaned Runs

> Amended by ADR 0036.

ADR 0029 promised that history lives exactly as long as its line in the listing, and orphaned Runs broke the promise from the other side: a Run directory no Entry names has no line, and lived forever. Two acts make one — `naiad queue rm`, which removes the Entry file and pointedly leaves the Run alone, and a Prune whose Run removal failed, which reports the orphan by path and then can never take it, because a Prune reaches Runs only through the done Entries that name them. "A thing the operator can act on" (ADR 0029) meant, in practice, `rm -rf` inside `~/.naiad` — exactly the by-hand surgery the Naiad-owned home exists to prevent.

We decided this belongs inside Prune rather than in a new command. After the done Entries and their Runs are taken, a Prune lists the Run store, and every directory no Entry names is judged by the same `status_of` reading the listing uses. An orphan that reads done or parked is removed. Done needs no argument. Parked deserves one, because Prune's own rule is that parked is a Run asking for a human and not Prune's to take — but that rule protects a Run someone will return to, and no one returns to an orphan: the Supervisor ticks Runs only through Entries, so an Entry-less Run can never advance, never be answered, and never reach a Terminal State. Its parking is permanent, and keeping an unreachable directory forever serves nobody.

A running orphan is skipped and named by path, every Prune, until the operator acts. Running is the one status that cannot distinguish a live Session still working from a dead one killed mid-work with nothing announced — and Naiad cannot look, because it never reads tmux or any Claude Code internals (ADR 0002). Liveness is a fact only the operator has, so the deletion is theirs. A directory that cannot be read at all is recorded as a failure and walked past, not a stop: the stop-early rule guards the Entry read, where deletion follows a misreading; here not deleting is the safe act, and one unreadable directory must not spare the rest of the orphans.

`naiad queue rm` does not change. It keeps removing only the Entry, and so keeps making orphans — which is now fine, because every orphan it makes is temporary: the next Prune takes it or names it. Teaching `rm` to take a done or parked Run too was rejected because it plants a second copy of Prune's selection rule where it can drift; Prune stays the one deleter of Runs. A separate `naiad runs prune` was rejected because the operator's intent behind `prune` is "remove finished history", an orphan is finished history without a line, and a second tidying verb is a distinction the operator must learn for no gain. Taking every orphan regardless of status was rejected because it deletes the Run log out from under whatever is still writing it.

## Consequences

A past Prune failure heals on the next Prune instead of accumulating. The retention sentence of ADR 0029 gains its missing half: history lives as long as its line in the listing, and what has no line lives only until the next Prune — except a running orphan, which lives until the operator, who alone can judge it, removes it by hand. Prune's cost grows by one directory listing of the Run store per invocation.
