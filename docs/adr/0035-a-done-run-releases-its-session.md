# A done Run releases its Session

> Excepted by ADR 0062.

Naiad's hooks are machine-wide, and each one acts only when a Run resolves from the session that fired it. A Run that reached its Terminal State kept resolving, because nothing released the Session it claimed. So the `SessionStart` hook injected the Protocol again at every Clear. A Terminal State declares no successor, so that Protocol closed by telling the agent to announce whichever State the Workflow calls for. The agent believed it and obeyed it: it raised a Question and declared a Wait. Naiad acted on neither, because `decide` returns Nothing for a finished Run. `RunLog.finished` already promised that an ending is final "however much the agent says afterwards". It made the ending final for Naiad alone. Nobody told the agent.

We decided that a Run which has ended releases its Session. `naiad.runtime.resolve` — the single seam through which a Run is identified — answers nothing for such a Run, at each of its three lookups. Everything else follows and needs no code of its own. The `SessionStart` hook prints nothing and succeeds, which is the path a session with no Run already takes. The `Stop` hook records nothing. The commands `state`, `ask`, `wait`, `hold` and `branch` refuse with the message that exists: "no run is attached to this session". The Session is free, so a Run adopted into it is the only match for its pane. Naiad cannot unset the environment variable in a live process. A variable naming an ended Run now falls through to the pane instead, and that fall-through is what lets the Adoption resolve.

A Run has ended when its latest Announcement names a Terminal State and carries no Question, **or** when the log records the Finish Naiad carried out. Either witness ends it. The Announcement is the earlier one, because the agent owns workflow progress (ADR 0001): it arrives before any tick, and it arrives at all when nothing watched the Run. The log line is the durable one. Only the latest Announcement is kept, so an agent that goes on announcing past its own ending overwrites the Terminal State that released its Session and takes the Session back — which is the failure this decision exists to remove, returning by the one door left open. The log line cannot be overwritten. When the Workflow file cannot be read, which State is Terminal cannot be known and the log line answers alone.

We rejected four alternatives. The first is a release notice printed by the hook, which tells the agent that the Run is over and the Session is the human's. It needs the ended Run to keep resolving, which is the opposite of a release. The refusal teaches the agent the same thing, and it teaches at the moment the agent types a verb. The second is an exemption for `naiad branch`, on the grounds that it states a fact rather than asks for an Action. A released Session resolves no Run at all, and the stored Working branch survives the release untouched, so a later Entry's Predecessor still reads it. The third is a pane rule that prefers the live Run to the oldest one. Once the ended Run stops claiming its pane, nothing is left to prefer.

The fourth is to read the ending from `naiad.runtime.queue._run_status`, which the Queue listing and a Prune already share. That reading is the log line alone, so it drops the earlier witness this decision keeps: one tick late, and absent when nothing watched the Run. We took a second reader knowingly, against this repository's own preference for one home per fact. The two answer the same question and can disagree in one case: a Run that announced its Terminal State and was never ticked reads ended here and running there. That case heals itself, because the next tick decides Finish and writes the line the Queue is waiting for. It lasts only for an Orphaned Run, which no tick reaches. A Session and a Queue want different authorities: the Session belongs to the agent working in it, and the Queue records what Naiad did.

## Consequences

A Session can now hold a second Run. An Adoption into the Session of a finished Run is an ordinary act, where before it made a Run that nothing could resolve or drive.

An Orphaned Run releases its Session by the same reading as any other: its agent announced a Terminal State. Prune keeps its own reading and is not changed here. So an orphan whose Terminal Announcement was never ticked releases its Session, and a Prune still names it as running and leaves it for the operator. Prune's caution is about deleting a Run that may be live, and the release deletes nothing, so the two do not need the same answer.

The release is complete only from the next Clear. Before that Clear the agent still holds the Protocol it read earlier in the same context, and nothing erases what it knows. The refusal corrects it, and the refusal arrives when the agent types a verb rather than when the Run ends.

Naiad loses its way back from a Session to the finished Run that used it. One command asks for that. `naiad watch` takes a Run id, and it falls back to this session when the operator gives none. Typed in a released Session, it used to report that the Run had already finished; now it says no Run is attached. Both answers stop the operator, and neither drives anything. We accept the plainer message, because a Session that answers for a Run it has released is the whole failure this decision removes. The Supervisor is unaffected: it reads the store.
