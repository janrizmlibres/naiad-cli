# Answerer fallback rides the invocation

An Answerer whose Model is unavailable does not fail loudly. The headless CLI prints "There's an issue with the selected model…" and exits zero, so Naiad reads a platform error message off stdout and types it into the asking session as though it were the answer. That is not the wrong-price degradation ADR 0026 accepted for a State — it is a wrong answer delivered mid-Run with nobody watching, on the one path where every Question's reply recurs.

The fix is not Naiad's to build, because the platform already built it. `claude --fallback-model` takes a comma-separated list and tries each model in order when the selected one is overloaded or not available — and it works only with `--print`, which is precisely the Answerer's mode. So the Workflow file's `[answerer]` table gains an optional `fallback` key, an opaque string Naiad forwards as the flag's value and never parses, exactly as ADR 0026 treats `model`. Absence means no flag, which is the behavior every existing file already has. Naiad keeps no model list, learns no failure semantics, and writes no detection or retry code: the platform detects, the platform degrades, and the author who wants a chain declares it beside the model they already name.

Three shapes were rejected on the way here. A chain hardcoded in Naiad is the rotting allowlist ADR 0026 refuses — a stale chain fails the same way the original name did, twice, before anyone notices. A Naiad-side retry with the `--model` flag dropped would have worked, but it required Naiad to build the detection the flag makes unnecessary, and detection was the only hard part. And extending the fallback to States is not possible on the platform's terms: the flag is `--print`-only, States are interactive, and detecting a failed model inside a live session is the confirmation channel ADR 0026 refuses and the internals-reading ADR 0002 forbids.

So the asymmetry is principled rather than accidental: the Answerer is the one headless invocation Naiad makes, so it is the one place a fallback can exist without Naiad inventing failure detection. The States keep their existing soft failures — a dropped `/model` runs on the sticky previous model (ADR 0026), and usage exhaustion mid-Run falls through the silence rule to a park (ADR 0021), which is the honest outcome: the reset time lives only inside the session, where ADR 0002 keeps Naiad from reading it, so auto-resume would be guessing.

## Consequences

A Workflow author can make the Answerer survive its model being unavailable or exhausted by declaring one key; a file that declares none behaves exactly as before. Which model actually answered becomes invisible to Naiad — the platform switches silently, so a degraded answer looks like any other — which is the same not-knowing ADR 0026 already accepts for a State's `/model`. The caveat accepted knowingly: "overloaded or not available" is the platform's phrase, and that it covers usage exhaustion is the platform's claim rather than something verified by test, because verifying it means burning a quota window. If the claim is false, the failure mode is today's — error text as an answer — and no worse.
