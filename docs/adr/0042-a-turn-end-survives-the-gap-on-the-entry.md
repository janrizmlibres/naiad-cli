# A Turn end survives the gap on the Entry

An Adoption's first delivery waits for the adopting Turn to end (ADR 0028) — and the ending is reported by the `Stop` hook, which records it against the Run it resolves for the pane. But an Adoption's Run does not exist when that Turn ends. `naiad adopt` writes an Entry and returns mid-Turn; the Run is created by the Supervisor's pass, and nothing bounds the gap between the two — the incident that surfaced this had no Supervisor running at all when the Turn ended. The hook resolved no Run, recorded nothing by design, and the Run then waited for a signal that had already come and gone. The hang rule catches the wait — a Run's own record counts among the signal files precisely so that an unsignalled Run is idle since it started — but catching it means notifying the human after the hang bound, not delivering the Prompt. The Adoption the operator asked for never starts unless they type into the session themselves.

The decision: **the `Stop` hook, finding no live Run for its pane, records the Turn end against the queued Entry claiming that pane — and the Supervisor relocates the record into the Run when it attaches.** The glossary already says an Entry is precisely a Run that does not exist yet, so a Turn end owed to the future Run has a natural home before that Run exists. The adopting Turn cannot end before the Entry is written, because `naiad adopt` runs inside it — so the window is closed exactly, not narrowed.

Subsidiary choices, each a real fork:

- **A sidecar in the queue directory, not a field on the Entry.** The record lives beside the Entry under its id (one file per Entry), written by the hook alone. On the Entry itself it would have two writers — the hook, and the Supervisor's attach — each rewriting the whole file atomically, and a hook firing during attach would silently lose one side's write: the same dropped-fact disease this decision treats. The sidecar keeps one writer per file, and it leaves with its Entry when the Entry is removed or pruned.
- **Not a pane-keyed store.** A Turn end is arguably a fact of the Session, and a per-pane record would say so — but it would be a second machine-global thing beside the Queue, against the rule that everything Naiad tracks belongs to a Run, and it would need a lifecycle of its own that the Entry's answers for free.
- **Attribution stays in the resolution seam.** `naiad/runtime/resolve.py` is the single seam through which a Run is identified; it grows the second question — "or the Entry awaiting attachment to this pane" — rather than the `stopped` handler asking the Queue itself. The order is fixed in one place: a live Run by pane first, a queued Entry claiming the pane second. Two call sites each composing that order is how the orderings drift apart.
- **Relocation, not copying — and write-if-absent.** At attach the Supervisor moves the sidecar into the run root as the Run's turns record and deletes it, so the fact keeps one home (ADR 0013's real rule; that ADR is amended rather than contradicted, because this record is written by the party that observed the fact, not a status copied from a Run). If the hook fired in the sliver after run-creation, a turns record already exists in the run root with a fresher count; the sidecar is then deleted unread. The opening only ever asks whether the count is above zero, so no merge is owed. The reverse interleaving — the hook resolved the Entry, the attach then relocated an absent sidecar, and only afterwards did the hook's write land — is closed from the hook's side: having written, it resolves again, and finding a Run now answering for the pane it performs the same move itself. Whichever side acted last moves the record, so no ordering orphans it.
- **The contract stays "a Turn has ended since adoption", not "the session is idle now."** A human who keeps conversing in the session after adopting can still be typed over when the Lane frees. That is the existing meaning of a recorded Turn end for every delivery, and tightening it would mean reading Claude Code internals (ADR 0002). Rejected with it, for the same reason from the other side: seeding a Turn end unconditionally at attach (delivers into a Turn still running whenever the Lane frees fast), delivering after a fixed quiet interval (the same, for any Turn longer than the interval), and blocking `naiad adopt` until the Turn ends (an agent's tool call must not block, ADR 0028).

## Consequences

The `Stop` hook now writes into the queue directory, not only into run roots: the Queue holds one more kind of file, owned by the Entry's lifecycle. ADR 0013 gains an amendment note saying so.

The hang rule stops being the only thing standing under an Adoption whose Turn ended in the gap: it remains the net for a session that truly dies, while the ordinary case — the adopting Turn ending before the Supervisor's pass — now delivers instead of notifying.

A Turn ending in a pane nobody adopted still records nothing, exactly as before — the hook's no-Run, no-Entry path stays silent, which is what keeps it installable machine-wide.
